# Client readiness audit — 6 November 2026

## Application remediation follow-up

Implemented application-level fixes after the audit: bounded 1,000-record recommendation candidates with deterministic ordering and visible scope, per-process public request limiting (120/minute per socket IP), valid-key operator access despite failed-attempt throttling, bounded throttle maps, browser security headers and no-store admin responses, timeframe-preserving exports, 200-character search input and field-specific API errors, unavailable history entries without broken links, explicit 200-bookmark addition limit with preserved legacy overflow accessible in groups, continuous Trending ranks, and recovery to the last valid API page. Personalization copy was already current in the workspace when remediation began. The historical findings below describe the original audit, not the current source state.

Deployment remains excluded: no container rebuild/restart, hosting, TLS, HSTS, trusted proxy configuration, or distributed rate-limit infrastructure was changed. In-process limits use the socket IP; deployment should configure its proxy/rate-limit strategy. Recommendations now cover the most recent 1,000 matching records, not the entire historical collection. Existing running containers retain their prior code until rebuilt. Full database integration and real-device visual sign-off remain outstanding.

Verdict: address the demonstrated functional issues before a client demonstration. Public-production security sign-off is not granted by this audit. No application code or database records were changed. Opening a real item added normal browser-local reading activity.

## Positive controls observed

- Operator metrics without credentials returned 401; operator key is not stored by Dashboard in browser storage.
- Invalid UUID and excessive page size returned controlled 400 responses.
- SQL-like and script-like search probes returned empty data rather than database errors; this small sample is not proof against all injection variants.
- Source fetching uses fixed approved endpoints, denies redirects, and bounds response size/time. Application database operations use Prisma.
- React text rendering and HTTP(S) link checks reduce obvious injection paths; original source links use safe new-tab attributes.
- AI assistant and enrichment remain disabled as required by the current approved phase.
